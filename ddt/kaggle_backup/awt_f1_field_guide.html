1Research framing

When a narrative is genuinely nonlinear — several interleaved threads, flashback framing, events that converge across threads at a shared moment — how much of a language model's apparent temporal reasoning survives, how much of it is memorized world-knowledge rather than text-grounded inference, and does decomposing the task into an explicit, checkable graph pipeline recover some of that gap and reveal exactly where reasoning breaks down?

Two methods are compared head to head on the same passages: a one-shot direct baseline (ask the model for the whole timeline in one call) and a graph pipeline that decomposes the task into extraction, deterministic repair, and deterministic verification stages. Both are scored by the same metric, described in §3, so the comparison is apples-to-apples.

2Methodology: two pipelines

Both methods start from the same input: a passage of numbered sentences whose surface order is scrambled relative to the true, multi-thread chronology — the model never sees the gold ordering, only prose. Node ids are the sentence numbers (s1…s36), so predicted and gold nodes correspond by construction (see §3's scope note).

Stage-by-stage

  1. Node extraction LLM — for each sentence, the model outputs its id and a short thread label (its own invented string, e.g. "Inspector" — it never sees gold's label "P").
  2. Edge extraction LLM — the model proposes Allen-relation edges between node pairs it judges related, plus candidate convergence groups: sets of node ids (across threads) it believes describe the same moment, each grounded in a quoted shared textual detail.
  3. Path-Consistency Repair (PCR) deterministic — for every same-thread triangle of predicted edges, checks Allen's composition table (metrics/allen_composition.py) for transitivity violations. If ≥2 independent witness paths agree on a fix, repairs the edge to the relation closest (by conceptual-neighborhood distance) to the model's original guess. If evidence is too thin or contradictory, logs the conflict and leaves the edge unchanged rather than guessing.
  4. Per-thread topological sort deterministic — Kahn's algorithm orders each thread's own events using only that thread's precedence-implying edges.
  5. Convergence-Order Consistency (COC) deterministic — takes every surviving cross-thread convergence candidate, converts it to a point (position in thread A, position in thread B) using the orders stage 4 just computed for free, and keeps only the largest mutually order-consistent subset per thread pair via longest-increasing-subsequence (patience sorting).
  6. Cross-thread alignment deterministic — merges the per-thread orders at COC's verified convergence anchors into one final global order.

3The metric: AWT-F1

Plain Exact Match collapses toward zero on long sequences even when a model is nearly right; Kendall's tau / pairwise ordering accuracy only ever asks "before or after," discarding 11 of Allen's 13 relations and any notion of a near-miss. Neither scores thread attribution or cross-thread convergence detection at all. AWT-F1 is the harmonic mean of three sub-scores built specifically to keep each failure mode visible on its own.

3.1 — Relation score (near-miss-aware)

Foundation: Allen's interval algebra Allen 1983 — 13 relations fully determined by the ordering of two intervals' 4 endpoints {s₁,e₁,s₂,e₂}. The distance between two relations is how many of the 6 pairwise endpoint comparisons disagree, derived directly from each relation's formal definition rather than copied from a hand-drawn diagram — it reproduces the structure of Freksa's conceptual neighborhood graph Freksa 1992 exactly, but is exact and unit-testable.

# metrics/allen_relations.py distance(gold, predicted) = |{ (p,q) ∈ 6 endpoint pairs : cmp(p,q) differs }| edge_score(gold, predicted) = max(0, 1 − distance / 6) relation_score(story) = (1/|E_gold|) · Σ edge_score(g_i, p_i) over every gold edge (missing predicted edge → scores 0; vacuously 1.0 if E_gold = ∅)

before vs meets disagree on exactly 1 of 6 comparisons → score 5/6 ≈ 0.833 (a near-miss). before vs during disagree on more → a lower score, reflecting a structurally different claim about the scene.

3.2 — Thread-attribution accuracy

The model can never reproduce gold's exact label string, so accuracy is scored against the best one-to-one correspondence between predicted and gold thread-label vocabularies (found by brute-force permutation over a contingency table — thread counts per story are always small, 3–6).

# best_mapping = argmax over permutations π of Σ contingency[gold_i, π(pred_i)] thread_attribution_accuracy = (# gold events whose mapped predicted thread = gold thread) / |events_gold| (a gold event with no matching predicted id counts as wrong)

3.3 — Convergence F1

Standard precision/recall/F1 over unordered same-moment node-id pairs.

precision = |gold_pairs ∩ pred_pairs| / |pred_pairs| recall = |gold_pairs ∩ pred_pairs| / |gold_pairs| F1 = 2·precision·recall / (precision + recall) both empty → vacuously (1, 1, 1) gold empty, prediction non-empty → (0, 0, 0) # a hallucinated convergence is a real error

3.4 — Combining them: harmonic mean, deliberately

AWT-F1 = harmonic_mean(relation_score, thread_attribution_accuracy, convergence_F1) = n / Σ(1/scoreᵢ), n = 3 — and exactly 0 if any scoreᵢ ≤ 0 memorization_gap = AWT-F1(original) − AWT-F1(counterfactual) # per sub-score too

An arithmetic mean would let a model that's perfect on two dimensions and totally fails the third post a comfortable ~0.6–0.7. Harmonic mean zeroes the headline score instead — this exact design choice is what surfaced this project's central empirical finding (§5): convergence detection failing almost everywhere while the other two dimensions look reasonable, a pattern an arithmetic mean would have buried.

Scope note — node correspondence

Predicted and gold nodes are matched by shared sentence-number id (s7 means the same sentence on both sides) because this pilot dataset is synthetic with numbered source sentences. This is simpler than CALLMSAE's Hungarian graph-similarity matching 2406.18449, the Set-Aligning Framework's Hausdorff-distance matching 2404.01532, or GEST's graph-matching similarity 2305.12940 — those solve the harder problem of aligning freely-generated predicted event text with no guaranteed correspondence to gold. This is a stated scope limitation, not an improvement over them, and would need addressing before AWT-F1 generalizes past a sentence-anchored dataset.

4Worked example: The Falling House

story_02 — four threads: P Inspector Voss's present-day arson investigation (days), F Elena's night of the fire, told via flashback (minutes), W Mrs. Kade the neighbor's log (days), S Marta, Elena's sister, recalling the same night — a flashback nested inside the flashback (minutes). 36 sentences, 40 gold edges, 2 gold convergence points.

4.2 — Gold convergence points

[s5, s6] — Elena's flashlight vanishing and Mrs. Kade's log entry both end at the instant the smoke alarm sounds. [s5, s25] — that same instant, from Marta's position in the car outside.

4.3 — What the model predicted

Node extraction produced its own thread-label strings (never gold's P/F/W/S): Inspector for s1,s3,s7,s9; Voss — a second, different label for the same person — for s10–s14; Elena for the F-thread events; MrsKade for W; Marta for S.

A genuine, specific error: one gold thread, two predicted labels

The model correctly grouped every P-thread event by content, but used two different label strings for the same investigator across the passage — "Inspector" early on, "Voss" later. Thread scoring maps predicted labels to gold labels one-to-one, so only one of the two can match gold P (here, "Voss" wins with 5 events vs. "Inspector"'s 4). The other 4 events — s1, s3, s7, s9 — are marked wrong, purely for this labeling inconsistency, even though the model never actually confused Voss with anyone else.

Edge extraction proposed 29 edges (against 40 gold edges) and 3 candidate convergence groups: {s5,s6,s25} ("the smoke alarm begins to blare / the alarm sounds / the alarm's wail reaches the car — all the same moment"), {s16,s23}, and {s20,s26}. PCR found zero transitivity violations in this story's edges (no repairs were needed — the model's local edge predictions were internally consistent, even where they missed gold edges entirely). 5Does the pipeline close the gap?

Partially — yes for consistency, not yet for recall. Here is exactly what PCR and COC fix, and what they structurally cannot touch.

5.1 — What PCR/COC demonstrably resolve (real example, story_04)

A different pilot story (story_04, chosen because story_02 above happened to need zero PCR repairs) shows PCR intervening for real. The model predicted s6 → s19: meets, but 5 independent transitivity paths through other predicted edges agreed this was inconsistent — PCR repaired it:

Sample of PCR's real repair log, story_04
EdgefromtoReason
s6, s19meetscontainsviolates transitivity with 5 witness paths in agreement; repaired to closest consistent relation
s6, s35meetsbeforeviolates transitivity with 5 witness paths in agreement; repaired to closest consistent relation
s4, s18meetsunchangedviolates transitivity with only 1 witness path (< 2 needed for confidence); left unchanged rather than guess

Story_04's full run: 10 edges repaired, 28 conflicts logged and honestly left alone (too little or too contradictory evidence to fix confidently) — PCR never silently forces a guess it can't justify. And in story_02 above, COC is what turned a 3-member grouped candidate into 5 concrete, gold-comparable pairs and verified all of them were mutually order-consistent — without COC's deterministic conversion, the raw grouped output isn't even in a form the scorer can compare against gold pairs at all.

5.2 — What remains open

The honest answer: the dominant bottleneck is not yet solved

PCR and COC are consistency layers — they clean up and verify candidates the model already proposed. Neither can invent a convergence pair the model never proposed in the first place, and neither can fix the model's edge-extraction call missing a relation entirely (the majority of story_02's 19 zero-score edges above are missing predictions, not wrong ones). Across the pilot set, convergence-point recall is the single largest driver of low AWT-F1 — several stories score convergence_F1 = 0.000 outright because the model's edge-extraction call proposed no usable candidates for that story at all, and no deterministic downstream stage can manufacture recall that was never generated upstream.

We do not yet have a mechanism that closes this specific gap. It is the correct next thing to design — options worth investigating (not yet built, not yet decided): a second, targeted LLM pass specifically prompted to hunt for convergence cues after the main extraction; a lower-level signal (shared timestamps/phrases) that seeds convergence candidates deterministically before the LLM step, rather than relying on it to notice; or accepting recall as a reported model-capability ceiling rather than an engineering problem to solve. This is flagged here exactly as open — to be researched and the answer added to this document later, not glossed over.
